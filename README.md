# LogiBridge: IoT Edge-to-Cloud Cold-Chain Monitoring Pipeline

This repository contains the end-to-end implementation for the M.Tech cold-chain monitoring project. The pipeline covers dataset generation, model training (M1 FP32), Post-Training Quantization (M2 INT8), Structured Pruning + PTQ (M3), and containerized edge deployment with OTA layer caching (Task D2).

## 🛠️ Complete Command Reference

Follow these steps in order within your project root virtual environment (`.venv`) to reproduce the entire pipeline.

### 1. Environment Setup & Dependencies

Install all required libraries for TensorFlow, Model Optimization, Pandas, MQTT and benchmarking (versions match CI):

```
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install tensorflow==2.21.0 keras==3.15.1 numpy==2.4.6 pandas==3.1.0 scikit-learn==1.9.1 tensorflow-model-optimization==0.8.1 tf-keras==2.21.0 psutil==7.2.2 paho-mqtt==2.1.0 matplotlib==3.11.2

```

### 2. Dataset Generation (Task D1)

Generate the synthetic sensor data streams representing Normal, Warning, and Critical operating conditions:

```
.\.venv\Scripts\python.exe training\generate_dataset.py

```

*Outputs:* `dataset_normal.csv`, `dataset_warning.csv`, `dataset_critical.csv`

### 3. Model Variant Training & Optimization

* **Variant M1 — FP32 Baseline Training:**
  Train the 2-hidden-layer MLP (32 and 16 units, ReLU activation) and verify it exceeds the 88% validation accuracy threshold:

```
  .\.venv\Scripts\python.exe training\train_model.py
  
```

  *Output:* `training/models/cold_chain_mlp_fp32.keras` (plus the same model as a TF SavedModel in `training/models/cold_chain_mlp_fp32_savedmodel/`)

* **Variant M2 — Post-Training Quantization (PTQ INT8):**
  Apply Full INT8 quantization using calibration samples via `tf.lite.TFLiteConverter`:

```
  .\.venv\Scripts\python.exe training\convert_ptq.py
  
```

  *Output:* `training/models/cold_chain_mlp_ptq_int8.tflite`

* **Variant M3 — Structured Pruning + PTQ INT8:**
  Apply 35% structured filter pruning with a PolynomialDecay schedule followed by INT8 PTQ. The schedule comes from `tensorflow_model_optimization`; whole hidden neurons are removed by the script itself, because tfmot's own pruning only zeroes individual weights and would not shrink the network (details in the F3 document):

```
  .\.venv\Scripts\python.exe training\prune_quantise.py
  
```

  *Output:* `training/models/cold_chain_mlp_pruned_int8.tflite` (and the pruned FP32 model `training/models/cold_chain_mlp_pruned.keras`)

* **Five-Metric Benchmark (Task F2):**
  Benchmarks M1, M2 and M3 on the held-out validation split: mean and p95 latency (200 runs after 10 excluded warm-up runs), file size, accuracy, and energy per inference (E = laptop TDP × mean latency, as in Lab 2 Step 3; psutil CPU % is reported alongside). Plug the laptop in first; pass `--tdp-w` if your CPU is not a 15 W i7-1255U:

```
  .\.venv\Scripts\python.exe optimisation\benchmark.py

```

  *Output:* `optimisation/results/benchmark_results.json` and a Markdown results table. The M1/M2/M3 quality-gate metrics from step 3 (`metrics_m*.json`) are written to the same folder.

* **Pareto Analysis (Task F2/F3):**
  Marks the Pareto-optimal variants across the five metrics and draws accuracy against latency, file size and energy with each frontier annotated:

```
  .\.venv\Scripts\python.exe optimisation\pareto.py

```

  *Output:* `optimisation/results/benchmark_results.csv` and `optimisation/results/pareto_chart.png`. The deployment recommendation built on these results (Task F3: deploy M3, keep M2 as the rollback) is in [`deployment/deployment_recommendation.md`](deployment/deployment_recommendation.md).

### 4. Docker Containerization & OTA Demo (Task D2)

* **Ensure Docker Engine is Running:**
  Start Docker Desktop on Windows:

```
  Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"
  
```

  Verify daemon health:

```
  docker ps
  
```

* **Build the Edge Container Image:**
  The image ships all three variants from `training/models/` (`cold_chain_mlp_fp32.keras`, `cold_chain_mlp_ptq_int8.tflite`, `cold_chain_mlp_pruned_int8.tflite`; committed, and regenerated by step 3) into `/app/inference/`, so `MODEL_PATH` takes just the file name. From the project root directory, run the build command targeting the inference Dockerfile:

```
  docker build -f inference/Dockerfile -t logi-edge:v1 .
  
```

* **Run the Container (with Environment-Based Model Switching):**
  The image defaults to M3 (`MODEL_PATH=cold_chain_mlp_pruned_int8.tflite`, the Task F3 recommendation). Switch variants without a rebuild, for example to the M2 rollback model:

```
  docker run -e MODEL_PATH=cold_chain_mlp_ptq_int8.tflite -e TRUCK_ID=truck_001 logi-edge:v1
  
```

  After the model, the service applies the brief's temperature bands (`inference/temperature_rule.py`): a window whose mean temperature is more than 1 °C from setpoint is at least `WARNING`, more than 3 °C is `CRITICAL`. The rule only raises the model's class. Each payload carries `status` (model + rule), `model_status` (model alone) and `temp_mean_c`; set the setpoint with `-e TEMP_SETPOINT_C=4.0` (the default).

### 5. PSI Drift Monitoring (Task E1)

Monitors the distribution of the model's P(Normal) output (published as `probabilities[0]` on `logibridge/trucks/{truck_id}/inference`) with a 4-bin PSI.

Build the reference from 300 clean inferences (simulator running with `--anomaly none`, ~50 min):

```
.\.venv\Scripts\python.exe monitoring\drift_monitor.py --mode reference
```

Monitor the last 100 inferences, PSI printed every 60 s, `[LOGIBRIDGE DRIFT ALERT]` when PSI > 0.25:

```
.\.venv\Scripts\python.exe monitoring\drift_monitor.py --mode monitor --log monitoring\psi_log.csv
```

### 6. Ansible Deployment (Task E2)

`deployment/logibridge_deploy.yml` deploys the inference container to the edge node in exactly 7 idempotent tasks; a second run with no changes reports `changed=0`. It ships M3 as `/opt/logibridge/model.tflite`; roll back to M2 with `-e model_src=<path to cold_chain_mlp_ptq_int8.tflite>`. Ansible does not run natively on Windows, so use WSL2 with **Ubuntu 24.04** (Ansible 14 requires Python 3.12+) and Docker Desktop's WSL integration enabled:

```
python3 -m venv ~/ansible-venv && ~/ansible-venv/bin/pip install ansible==14.5.0 docker==7.2.0
docker run -d --name registry -p 5000:5000 registry:2
docker tag logi-edge:v1 localhost:5000/logi-edge:v1 && docker push localhost:5000/logi-edge:v1
~/ansible-venv/bin/ansible-playbook -i deployment/inventory.ini deployment/logibridge_deploy.yml -K
~/ansible-venv/bin/ansible-playbook -i deployment/inventory.ini deployment/logibridge_deploy.yml -K
```

### 7. CI

`.github/workflows/ci.yml` runs on every push: sanity + unit tests → M1 training (gates: val accuracy > 88%, Critical recall > 95%) → M2 / M3 conversion (gated on INT8 accuracy) → image build → MQTT integration test of all three variants from the same image via `MODEL_PATH` → Ansible deployment run twice (second run must report `changed=0`).
